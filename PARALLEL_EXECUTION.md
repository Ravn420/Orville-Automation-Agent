# Parallel Execution Controls

## Overview

The orchestration engine now accepts `max_workers`. When more than one worker is configured, independent ready tasks are executed as a batch. Each handler receives a deep-copied context snapshot, preventing concurrent branches from mutating shared checkpoint state. Results are reconciled serially into the checkpoint in graph order.

## Safety boundaries

A task is eligible for a parallel batch only when its dependencies are satisfied, its condition is true, it is not awaiting approval, and it is not terminal. Static `owned_paths` conflicts are rejected during graph validation. Dynamic filesystem locks and branch merge semantics remain required before parallel tasks can safely edit overlapping resources.

Handlers should return self-contained outputs. A branch cannot observe outputs generated by another task in the same batch; it can observe only outputs that were checkpointed before the batch began. Downstream tasks run after reconciliation and can consume all completed upstream outputs.

## Failure and recovery

Each branch result is reconciled independently. A failed branch becomes `failed` and follows its configured retry limit on a later scheduler pass. Successful branches become `verified` unless an independent verifier rejects them. Checkpoint persistence occurs before the batch and after reconciliation, so completed branch outputs and failures survive interruption.

## Timeouts and cancellation

Per-task timeouts are applied inside worker execution. A timeout is persisted as a task failure and follows the existing retry policy. Thread-based timeout handling cannot forcibly terminate uncooperative Python code; hard termination requires process isolation and cooperative cancellation. Run cancellation is checked at scheduler boundaries and marks unfinished tasks as cancelled.

## Limitations

The current parallel implementation is in-process and thread-based. It does not yet provide distributed workers, durable leases, dynamic locks, process isolation, resource quotas, stream-level backpressure, or atomic multi-file branch merges. These requirements remain on the roadmap before production use for high-risk or large-scale workloads.
